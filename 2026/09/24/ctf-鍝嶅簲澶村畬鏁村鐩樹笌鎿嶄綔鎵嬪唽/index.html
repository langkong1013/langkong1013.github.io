【基础】响应头

零基础详解版 —— 每一步都讲清「作用 · 原理 · 为什么这么做」

平台：ctf.bi6pcr.com | 题目：响应头（60 分 · Web / 基础）

一、题目回顾

题目描述：flag 不在页面正文里。按 F12，看这一次响应的响应头，有一项叫 X-Flag。

题目提示：开发者工具 → 网络 → 点开文档请求 → 响应标头。

一句话思路：

服务器把 flag 放在了 HTTP 响应头的一个自定义字段 X-Flag 里，页面正文不显示它。用开发者工具的“网络/响应标头”或命令行 curl -i 就能看到并读出 flag。

结果：响应头中 X-Flag 字段的值即 flag。

说明：flag 在你的实例站点里，需要你自己访问获取；本手册把方法与原理讲透。

二、前置概念：HTTP 响应头是什么

2.1 一次 HTTP 交互长什么样

你访问网页时，服务器返回的内容其实分两部分：响应头（说明信息） 和 响应正文（网页内容）。

HTTP/1.1 200 OK ← 状态行（200 表示成功）
Content-Type: text/html ← 响应头：内容类型
Set-Cookie: sess=abc123 ← 响应头：设置 Cookie
X-Flag: CTF{…} ← 响应头：自定义字段（本题 flag 在这）
← 空行（头与正文的分界）

... 页面正文 ... ← 响应正文

2.2 常见的响应头

响应头 作用
Content-Type 正文是什么类型（text/html、image/png…）
Content-Length 正文长度
Set-Cookie 让浏览器保存 Cookie
Location 重定向目标
Server 服务器软件及版本
X-Powered-By 后端技术（如 PHP）
X-Flag 等 X- 开头的 自定义响应头，常用于放额外信息（本题 flag 就放这里）

2.3 为什么 flag 会藏在响应头里

页面正文是“给人看的”，而响应头是“给浏览器/程序看的”。服务器可以自定义响应头（一般以 X- 开头），把不想显示在页面上的信息（如本题的 flag）放进头里——这就是本类题目的考点。

三、完整操作步骤（Step by Step）

Step 0 开实例并打开页面

wsrx connect ‘把那条 wss://… 粘到这里’

浏览器打开它映射出来的 http://127.0.0.1:端口

Step 1（推荐）F12 → 网络 → 响应标头

  • 按 F12 打开开发者工具，切到 Network（网络）；
  • 刷新页面（F5）——不刷新的话网络列表可能是空的；
  • 在请求列表里点第一条“文档”请求（名字通常就是你的地址，Type 为 document）；
  • 右侧切到 Headers（标头），往下找到 Response Headers（响应标头）；
  • 找到 X-Flag: CTF{…} —— 冒号后面的就是 flag。

Step 2 命令行方式（更快）

curl -i http://127.0.0.1:端口/

作用：-i 让 curl 把响应头和正文一起打印出来。

在输出里找这一行：X-Flag: CTF{…} —— 等号/冒号后面就是 flag。

Step 3 提交 flag

把 X-Flag 的值复制到题目页提交框，点“提交 flag”。

四、原理详解：为什么这算“信息泄露”

响应头在页面里“看不见”，但它是完整返回给浏览器的，任何人都能用开发者工具/curl 看到。开发时若把敏感信息（密钥、flag、内部地址）放进响应头，就相当于“明信片背面写了一行字”——收件人之外的人也能翻看。这类“藏在协议细节里的信息”是 Web 信息收集/信息泄露的常见考点。

五、易错点

现象 / 报错 原因 解决
Network 列表是空的 没刷新页面 按 F5 刷新，再点文档请求
看的是请求头 选错了分区 要看 Response Headers（响应标头），不是 Request Headers
curl 看不到 X-Flag 没加 -i（只显示了正文） curl -i 才会显示响应头
提交说错误 复制带了 “X-Flag:” 或空格 只复制冒号后面的值本身
页面打不开 实例过期 / 端口变了 重开实例、重连 wsrx，用新端口

六、速查卡

一句话记法：F12 → 网络 → 文档请求 → 响应标头 → 找 X-Flag。

命令行一行（-i 显示响应头）：

curl -i http://127.0.0.1:端口/

输出里找： X-Flag: CTF{…}

附录：常见响应头与自定义头（Web 拓展）

头 含义/考点
X-Flag / X-Secret 等 自定义头藏 flag/密钥（本题）
Set-Cookie Cookie 题（“小饼干”那题）
Location 302 跳转题，常配合 to 参数
Server / X-Powered-By 指纹识别：判断服务器/框架版本，找已知漏洞
Content-Type 配合 XSS（text/html）、文件上传等
Access-Control-Allow-Origin CORS 跨域配置问题

学习方法：这类“看头/看 cookie/看源码”的题，本质都是同一个技能——用开发者工具把一次 HTTP 交互的每个部分都看一遍。
