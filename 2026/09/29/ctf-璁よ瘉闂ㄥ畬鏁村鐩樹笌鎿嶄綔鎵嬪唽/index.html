认证门（HTTP Basic 认证 401）

langkong10132026-09-292026-10-28

零基础详解版 —— HTTP Basic 认证原理、401 与 WWW-Authenticate、base64 凭据，Python 代码逐行讲解

一、题目信息

项目 内容
题名 认证门（页面显示 401）
页面 返回 401 Unauthorized，要求 Basic 认证；正文注释里藏着账号密码
题型 Web —— HTTP Basic 认证 / 凭据泄露
最终 flag flag{gate_44f175dcb291}

二、题目现象

裸访问首页，服务器返回状态码 401，并在响应头里要求认证：

HTTP/1.0 401 Unauthorized
WWW-Authenticate: Basic realm=”gate”
Content-Type: text/html; charset=utf-8

401

关键信息 含义
401 Unauthorized 需要身份认证才能访问
WWW-Authenticate: Basic realm=”gate” 认证方式 = Basic，领域名 = gate
注释里泄露了”用户名:密码”

三、前置知识（零基础也能懂）

3.1 HTTP 状态码与 401

服务器用三位数字告诉客户端结果：200=成功，401=没认证，403=认证了但没权限，404=找不到。401 的意思是”你得先登录”。

3.2 HTTP Basic 认证是什么

Basic 认证是最简单的一种登录：客户端把”用户名:密码”拼起来，做 Base64 编码，塞进请求头 Authorization 发给服务器。

用户名:密码 -> ctf:summer
Base64 编码 -> Y3RmOnN1bW1lcg==
请求头 -> Authorization: Basic Y3RmOnN1bW1lcg==

3.3 Base64 不是加密

Base64 只是”把字节转成可打印字符”的编码，谁都能一秒解回来。看到 Basic 认证，把它解出来就是明文账号密码。

3.4 为什么要看 401 的正文

服务器在拒绝你时，有时会顺手在页面里放提示（本题就是注释 ）。所以”被拒绝的那一页”也要逐字看。

四、解题思路（为什么这么做）

  • 第 1 步：访问首页得到 401 + Basic realm=”gate”。→ 知道它要账号密码。
  • 第 2 步：401 页面正文的注释 泄露了凭据。
  • 第 3 步：带着 Authorization: Basic <base64(ctf:summer)> 再请求，flag 到手。

一句话：401 别只看状态码，把响应头和正文都读一遍，凭据常常就写在里面。

五、逐步操作（三种方式，任选其一）

方式一 浏览器（最直观）

  • 打开页面 → 弹出登录框（这就是 Basic 认证的界面）。
  • 用户名填 ctf，密码填 summer → 登录后页面直接显示 flag。
  • （提示哪里来？F12 → Network 里那条 401 响应的正文注释里。）

方式二 curl 一行（-u 自动帮你做 Base64）

curl -s -u ctf:summer http://127.0.0.1:<端口>/

片段 作用
-u 用户名:密码 curl 自动拼好并 Base64，塞进 Authorization 头
-s 安静模式

方式三 Python（推荐，全自动）

import re, requests

base = ‘http://127.0.0.1:<端口>’

1) 先裸访问，观察状态码和响应头

r = requests.get(base + ‘/‘)
print(r.status_code) # 401
print(r.headers.get(‘WWW-Authenticate’)) # Basic realm=”gate”
print(r.text) # 正文里藏着

2) 从正文的注释里抠出”用户名:密码”

m = re.search(r’‘, r.text)
user, pwd = m.group(1), m.group(2)
print(‘拿到账号:’, user, pwd)

3) 带上 Basic 认证再请求一次

r2 = requests.get(base + ‘/‘, auth=(user, pwd))
flag = re.search(r’flag{[^}]*}‘, r2.text).group(0)
print(‘flag =’, flag)

代码 作用 · 原理
requests.get(base + “/“) 第一次裸请求，会得到 401
r.status_code 查看状态码（就是 401）
r.headers.get(‘WWW-Authenticate’) 读取认证方式提示：Basic realm=”gate”
re.search(r’‘, r.text) 从注释里抠出 用户名 和 密码
requests.get(base+”/“, auth=(user, pwd)) 带 Basic 认证重新请求（requests 自动做 Base64）
re.search(r’flag{[^}]*}‘, r2.text).group(0) 从成功响应里取出 flag

补充：只能走 wss 隧道时（手工拼 Authorization 头）

import base64, ssl, websocket

URL = ‘wss://ctf.bi6pcr.com/api/proxy/<实例uuid>’
cred = base64.b64encode(b’ctf:summer’).decode() # 得到 Y3RmOnN1bW1lcg==

ws = websocket.create_connection(URL, timeout=25,
header=[‘Origin: https://ctf.bi6pcr.com'],
sslopt={‘cert_reqs’: ssl.CERT_NONE})
ws.send(‘GET / HTTP/1.1\r\nHost: 127.0.0.1\r\n’
‘Authorization: Basic %s\r\nConnection: close\r\n\r\n’ % cred)
buf = b’’
while True:
try:
d = ws.recv()
except Exception:
break
if not d:
break
buf += d if isinstance(d, bytes) else d.encode(‘latin1’)
ws.close()
print(buf.partition(b’\r\n\r\n’)[2].decode(‘utf-8’, ‘replace’))

代码 作用 · 原理
base64.b64encode(b’ctf:summer’) 把凭据编码成 Base64 字符串
‘Authorization: Basic %s’ % cred 把 Base64 凭据写进请求头
buf.partition(b’\r\n\r\n’)[2] 按空行切开，取响应正文

六、结果

用户名:密码 = ctf : summer
Base64 = Y3RmOnN1bW1lcg==
带认证请求 -> 

flag{gate_44f175dcb291}

flag = flag{gate_44f175dcb291}

最终 flag：flag{gate_44f175dcb291}

七、易错点

现象 / 报错 原因 解决
一直 401 没带 Authorization 头 用 auth=(user,pwd) 或 -u user:pwd
用户名密码猜不到 没读 401 页面正文 注释 就是
Base64 拼错 自己手拼容易出错 交给 requests/curl 自动编码
浏览器不弹登录框 之前输错过被记住 换无痕窗口，或带上正确凭据

八、速查卡

思路：401 + Basic realm=gate -> 正文注释泄露 ctf:summer -> 带认证再请求

curl -s -u ctf:summer http://127.0.0.1:<端口>/

Base64 凭据

Authorization: Basic Y3RmOnN1bW1lcg== # = ctf:summer

结果

flag{gate_44f175dcb291}

附录：认证/凭据类题的通用套路

手法 怎么找
401 正文/注释泄露凭据 读被拒绝页面的全文（本题）
响应头泄露 WWW-Authenticate、Set-Cookie 里的 token
Base64 混淆 看到长串 Base64 先解码
默认弱口令 admin/admin、admin/123456 等
JWT 解 token 看 payload，尝试 alg:none
