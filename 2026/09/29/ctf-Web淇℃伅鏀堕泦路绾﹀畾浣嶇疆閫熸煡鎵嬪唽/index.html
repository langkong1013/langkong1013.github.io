Web 信息收集 · 约定位置速查手册

langkong10132026-09-292026-10-28

零基础详解版 —— 开题先扫什么、为什么扫、怎么扫（含可直接用的扫描脚本逐行讲解）

〇、一句话总纲

Web 找 flag 的题，本质是信息收集。比的不是”会不会破解密码”，而是谁知道更多”约定位置”（well-known 路径）和”藏东西的手法”。robots.txt 只是其中最有名的一个。

一、为什么想到 robots.txt？

1.1 位置固定、成本极低

任何网站，robots.txt 都只可能在一个地方——网站根目录：

http://任意网站/robots.txt

  • 位置是”约定俗成”的（有专门标准 RFC 9309），所以不用猜：要么给你文件，要么给 404。
  • 成本几乎为零：一次请求，命中了白赚一步，没命中也就浪费 0.1 秒。

所以它不像”猜密码”，更像进门先推一下门把手——推了不亏。

1.2 出题人为什么爱用它

robots.txt 的原本用途，是告诉搜索引擎爬虫”哪些页面不要抓”。作者得把”不想被随便看见的目录”写进去。

这就等于——他为了保护一个秘密，亲手把秘密的目录名告诉了所有人。CTF 出题人正是利用这个”藏一半、露一半”的心理。所以当首页一片空白、什么线索都没有时，第一反应就是它。

1.3 是不是每道题都能查？

不一定有，但一定值得查。

情况 表现 怎么办
有放 返回 Disallow: /xxx 顺着路径走，白送一步
没放 返回 404，或返回默认页 跳过，换下一种探测

关键心态：它不是你”要解的题”，而是你”要养成的顺手动作”。

⚠️ 实战教训：有些服务器对不存在的路径也返回 200（回一个默认页面）。所以不能只看状态码，要看内容是不是”默认页”——内容不一样才是真命中。

二、约定位置总清单（收藏这一页）

2.1 站点的”官方公开文件”

路径 作用 能挖到什么
/robots.txt 爬虫协议 隐藏目录名
/sitemap.xml 站点地图 全站 URL 列表
/.well-known/security.txt 安全联系方式 有时含内部信息
/humans.txt 网站作者/团队 人名、账号、技术栈
/favicon.ico 网站图标 指纹可反查框架/其他站点

2.2 源码 / 版本控制泄露（威力最大）

路径 说明
/.git/config、/.git/HEAD 版本库泄露 → 可拉出整站源码
/.svn/、/.hg/ SVN、Mercurial 同类泄露
/.DS_Store macOS 目录索引 → 泄露文件名
/.env、/config.php、/config.json 配置文件 → 数据库密码、密钥
/index.php.bak、/index.php~、/index.php.swp 备份/交换文件 → 源码

2.3 备份包（经典送分）

/backup.zip /www.zip /web.zip /wwwroot.zip
/backup/ /bak/ /backup.tar.gz

2.4 接口 / 调试 / 后台

路径 说明
/api、/api/v1、/swagger、/openapi.json 接口文档
/actuator、/actuator/env Spring Boot 监控端点（泄露配置）
/console、/h2-console 调试控制台
/server-status、/nginx_status 服务状态
/admin、/login、/manage 后台入口
/debug、/test、/dev 调试页

三、除了”文件路径”，还有这些”位置”

位置 怎么找
响应头 X-… 自定义头、Set-Cookie（如”收据”题的 X-Next）
网页源码注释 或
源码里的外链 src= / href= 指向的 JS/CSS（如”档案”题的 /a.js）
JS 文件 里面写死的接口地址、密钥、后门参数
404 页面 有时会报出真实路径或框架信息
URL 查询参数 ?debug=1 ?test=1 等隐藏开关（如”车间”题）

四、怎么系统化地扫（别一个个手敲）

4.1 手动先试 5 个固定的

robots.txt、sitemap.xml、.git/config、.env、backup.zip

4.2 用工具跑字典

dirsearch、feroxbuster、ffuf、gobuster、dirb —— 用字典文件批量请求，自动筛出”存在但没链接”的路径。

例：dirsearch（Python 工具）

dirsearch -u http://127.0.0.1:<端口>/ -e php,html,js,txt,zip

4.3 自写一个最小扫描器（逐行讲解）

import requests

base = ‘http://127.0.0.1:<端口>’ # 目标根地址（换成实例地址）

words = [‘robots.txt’, ‘sitemap.xml’, ‘.git/config’, ‘.env’,
‘backup.zip’, ‘www.zip‘, ‘phpinfo.php’,
‘admin/‘, ‘api/‘, ‘.DS_Store’] # 要试的”约定位置”清单

for w in words: # 逐个路径去试
url = base + ‘/‘ + w # 拼出完整网址
try:
r = requests.get(url, timeout=5) # 发请求，5 秒超时防止卡死
except Exception:
continue # 请求失败就跳过，不影响后面
body = r.text[:200].lower() # 取正文前 200 字符并转小写
if r.status_code == 200 and ‘doctype’ not in body:
print(‘命中:’, url, r.status_code) # 200 且”不是默认网页”才算命中

逐行讲解：

代码 作用 · 原理
base = ‘http://127.0.0.1:<端口>’ 目标根地址，所有探测都基于它拼路径
words = […] 要试的路径清单；想更狠就换成几千行字典文件
for w in words: 逐个取出路径
url = base + ‘/‘ + w 拼成完整 URL，例如 …/robots.txt
try / except: continue 网络请求可能超时/报错，跳过保证不中断整个扫描
requests.get(url, timeout=5) 发 GET 请求；timeout=5 = 最多等 5 秒防卡死
r.text[:200].lower() 取正文前 200 字符并转小写，用于判断”是不是默认页”
if r.status_code == 200 and ‘doctype’ not in body: 双重条件：状态码 200 且正文不是默认页才算命中
print(‘命中:’, url, …) 只打印真正”内容不一样”的命中项

4.4 进阶：换成字典文件（dirsearch 的核心思想）

import requests

base = ‘http://127.0.0.1:<端口>’

打开字典文件（每行一个路径），这是 dirsearch 等工具的核心思想

with open(‘dict.txt’, encoding=’utf-8’) as f:
words = [w.strip() for w in f if w.strip()] # 去掉空行和首尾空白

for w in words:
url = base + ‘/‘ + w
try:
r = requests.get(url, timeout=3, allow_redirects=False)
except Exception:
continue
# 只报”可能有价值”的：200 / 403 / 302
if r.status_code in (200, 403, 302) and ‘doctype’ not in r.text[:200].lower():
print(r.status_code, url)

逐行讲解：

代码 作用 · 原理
with open(‘dict.txt’, encoding=’utf-8’) as f: 打开字典文件（每行一个路径）
[w.strip() for w in f if w.strip()] 列表推导：逐行去空白，滤掉空行
allow_redirects=False 不允许自动跳转，好在结果里看到 302 本身
if r.status_code in (200, 403, 302) 只报 200/403/302 —— 403、302 也常是”有东西”的信号

五、页面空白时的排查优先级（背下来）

  1. robots.txt / sitemap.xml <- 最便宜，先试
  2. 源码注释 / src= / href= <- 看源码
  3. 响应头 X-* / Set-Cookie <- 别只看正文
  4. /.git/ / .env / 备份文件 <- 挖源码
  5. dirsearch 等工具跑字典 <- 系统化

六、实战对照（本系列题目都用了哪一招）

题目 线索位置 手法
维护中 /robots.txt Disallow 泄露 /s/note
门岗 /robots.txt → ROT13 → Hex 多步接力链
通知 首页源码注释 直接藏
档案 外链 JS /a.js src= 引用的文件里写 flag
车间 内联 JS 指路 /api/debug ?debug=1 参数开关后门
收据 响应头 X-Next（Base64） 正文干净、线索在头里
旧馆 首页注释给路径 + Base64 注释当路标，内容是编码
认证门 401 正文注释 Basic 认证凭据泄露

七、速查卡（可直接打印，开题照着扫）

===== 第 0 步：不管什么题，先打这 5 个 =====

curl -s http://目标/robots.txt
curl -s http://目标/sitemap.xml
curl -s http://目标/.git/config
curl -s http://目标/.env
curl -s http://目标/backup.zip

===== 第 1 步：看源码和响应头 =====

curl -s http://目标/ # 正文（找注释、src=、href=）
curl -s -D - -o /dev/null http://目标/ # 只看响应头

===== 第 2 步：上工具 =====

dirsearch -u http://目标/ -e php,html,js,txt,zip

===== 遇到编码先解，解出的再看看是不是路径 =====

base64 -d # Base64
xxd -r -p # 十六进制
tr A-Za-z N-ZA-Mn-za-m # ROT13

附录：常见编码速认表

编码 特征 怎么解
Base64 A-Za-z0-9+/ ，结尾 = base64 -d
Base32 A-Z2-7，结尾 = base32 -d
Hex 只有 0-9 a-f，成对出现 xxd -r -p / bytes.fromhex
URL 编码 形如 %E4%B8%AD urllib.parse.unquote
ROT13 字母全部位移 13 位 tr A-Za-z N-ZA-Mn-za-m
单字节 XOR 整串被同一密钥异或 用已知明文 “flag{“ 反推密钥
