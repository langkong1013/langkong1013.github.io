file.bin（嵌套与诱饵）

langkong10132026-09-262026-10-28

零基础手算详解版 —— ZIP/GZIP 嵌套解包 + 识别诱饵，Python 代码逐行讲解

一、题目信息

项目 内容
入口页 http://127.0.0.1:<端口>/ → 提供 file.bin
代理隧道 wss://ctf.bi6pcr.com/api/proxy/01a0dba5-f650-723e-ada0-734d46eb9a0b
附件 file.bin（其实是 ZIP，469 字节）
内含 readme.txt、flag.b64、archive.gz
题型 杂项 —— 嵌套压缩包 + 编码 + 诱饵识别
最终 flag flag{f13_f66e1b03f0b2}

二、前置知识（零基础也能懂）

2.1 文件类型看”魔数”，不看扩展名

类型 开头特征 file 显示
ZIP 50 4B 03 04（PK..） Zip archive data
GZIP 1F 8B gzip compressed data
Base64 文本 只含 A-Za-z0-9+/= 可打印字符 ASCII text

2.2 ZIP 与 GZIP 的区别

ZIP GZIP
能装几个文件 多个 通常 1 个
能否看列表 unzip -l 无（只有 1 个）
解压命令 unzip x.zip gunzip x.gz（或 gzip -d）

2.3 Base64

把任意数据用 64 个可打印字符表示，常见结尾 = 或 ==。本题两处都用到了它。

2.4 诱饵（decoy）

CTF 里常见手法：故意放看起来像答案的假 flag、或误导性的提示，让你以为解出来了。判断标准：真 flag 通常符合题目固定的格式（本题是 flag{3位_12位十六进制}）。

三、解题思路（为什么这么做）

  • 第 1 步：隧道取回 file.bin；用 file 看，发现是 ZIP。
  • 第 2 步：解压得到 readme.txt、flag.b64、archive.gz 三个文件。
  • 第 3 步：readme.txt 给了一条”提示”和一个 flag；flag.b64 解码又是一个 flag —— 先别急着交！
  • 第 4 步：逐个验证。发现两个 flag 都不符合题目格式（都是 “decoy / nothing” 之类），且提示照做是乱码 → 都是诱饵。
  • 第 5 步：解 archive.gz → 得到一段 Base64 → 解码 → 得到符合格式的真 flag。

四、逐步过程（核心）

4.1 取回 file.bin

curl -s http://127.0.0.1:<端口>/file.bin -o file.bin # 或走 wss 隧道，见 5.1

4.2 看类型

$ file file.bin
file.bin: Zip archive data, made by v2.0 UNIX …

开头是 50 4B 03 04（PK..）→ 就是 ZIP。

4.3 列出并解压

$ unzip -l file.bin # 先只看列表
Length Name
68 readme.txt
36 flag.b64
52 archive.gz
$ unzip file.bin # 解开

4.4 逐个检查（识别诱饵）

$ cat readme.txt
decode flag.b64 and xor with the gzip name
flag{nothing_to_see_here} <– 假 flag

$ cat flag.b64
ZmxhZ3t5b3VfZm91bmRfdGhlX2RlY295fQ==

把 flag.b64 解码看看：

$ base64 -d flag.b64; echo
flag{you_found_the_decoy} <– 又是假 flag

按 readme 提示”xor with the gzip name”去异或，结果是乱码（验证过）→ 提示是误导。

4.5 解开真正的 archive.gz

$ file archive.gz
archive.gz: gzip compressed data …
$ gunzip -c archive.gz
ZmxhZ3tmMTNfZjY2ZTFiMDNmMGIyfQ== <– 一段 Base64

再用 Base64 解码：

$ gunzip -c archive.gz | base64 -d; echo
flag{f13_f66e1b03f0b2} <– 符合格式，真 flag！

4.6 结论

文件 处理 结果 性质
readme.txt 直接看 flag{nothing_to_see_here} 诱饵
flag.b64 Base64 解码 flag{you_found_the_decoy} 诱饵
archive.gz gunzip 后 Base64 解码 flag{f13_f66e1b03f0b2} 真 flag

最终 flag：flag{f13_f66e1b03f0b2}

五、Python 代码逐行讲解

5.1 通过 wss 隧道取文件（fetch.py）

import ssl, websocket
URL = ‘wss://ctf.bi6pcr.com/api/proxy/01a0dba5-f650-723e-ada0-734d46eb9a0b’

def http(path, save=None):
ws = websocket.create_connection(URL, timeout=25,
header=[‘Origin: https://ctf.bi6pcr.com'],
sslopt={‘cert_reqs’: ssl.CERT_NONE})
req = (‘GET %s HTTP/1.1\r\nHost: 127.0.0.1\r\n’
‘Accept: /\r\nConnection: close\r\n\r\n’ % path)
ws.send(req)
buf = b’’
while True:
d = ws.recv()
if not d:
break
buf += d
ws.close()
if save:
open(save, ‘wb’).write(buf)
return buf

r = http(‘/file.bin’, save=’raw.bin’)
head, _, body = r.partition(b’\r\n\r\n’) # 去掉 HTTP 响应头
open(‘file2.bin’, ‘wb’).write(body)

代码 作用 · 原理
import ssl, websocket ssl 用于关证书校验，websocket 提供 WebSocket 客户端
URL = … 平台给的代理隧道地址
websocket.create_connection(…) 建立 wss 连接；CERT_NONE 跳过证书校验
‘GET %s HTTP/1.1\r\n…’ % path 手写 HTTP 请求报文；末尾空行表示请求头结束
ws.send(req) 通过隧道把请求发出去
ws.recv() 收数据（响应头 + 文件内容）
if not d: break 收到空数据 = 结束
r.partition(b”\r\n\r\n”) 按空行切掉响应头，剩下的是文件本体

5.2 解开三个文件拿到真 flag（solve.py）

import base64, gzip

1) flag.b64 : 直接 Base64 解码

b64 = open(‘flag.b64’, ‘rb’).read().strip()
print(‘flag.b64 ->’, base64.b64decode(b64).decode()) # 诱饵

2) archive.gz : 先 gzip 解压，把解出来的文本再 Base64 解码

inner = gzip.open(‘archive.gz’, ‘rb’).read() # 解压得到一段 base64 文本
print(‘archive.gz 解压 ->’, inner)
print(‘archive.gz 再解码 ->’, base64.b64decode(inner).decode()) # 真 flag

代码 作用 · 原理
open(‘flag.b64’,’rb’).read().strip() 读文件、去掉首尾空白（换行）
base64.b64decode(b64) Base64 文本还原成原始字节
.decode() 字节按 UTF-8 变成文字
gzip.open(‘archive.gz’,’rb’).read() 把 gzip 解压，读出里面的内容（是一段 base64 文本）
base64.b64decode(inner) 对解压出来的文本再 Base64 解码
结论 两层叠加：gzip 先解压，再 Base64 解码

六、在 Linux 上怎么跑（三种方式，含逐行讲解）

方式一 一行命令一条龙（推荐）

#!/bin/bash
set -e
unzip -o file2.bin >/dev/null
echo ‘— readme.txt —‘; cat readme.txt
echo ‘— flag.b64 解码 —‘; base64 -d flag.b64; echo
echo ‘— archive.gz 解压后再解码 —‘; gunzip -c archive.gz | base64 -d; echo

片段 作用
unzip -o file2.bin -o 覆盖同名文件
base64 -d flag.b64 -d 解码 Base64
gunzip -c archive.gz -c 输出到屏幕（不删原文件）
| base64 -d 管道：把 gunzip 的结果直接喂给 base64 解码

方式二 分步排查（适合新手练手）

file file.bin # 1 看类型
unzip -l file.bin # 2 看列表
unzip file.bin # 3 解压
cat readme.txt # 4 看说明(注意可能是诱饵)
base64 -d flag.b64 # 5 试试
gunzip -c archive.gz | base64 -d # 6 真路径

方式三 用 Python 一把梭

见 5.2 的 solve.py：python3 solve.py

七、易错点

现象 / 报错 原因 解决
file.bin 打不开 它其实是 ZIP，不是二进制数据 按 Zip 解压
直接交了 you_found_the_decoy 那是诱饵 核对是否符合作答格式
照 readme 做得到乱码 提示本身是误导 回到 archive.gz 走 gzip+base64
gunzip 报错 用了 gunzip 却没加 -c 用 gunzip -c 输出到屏幕
decode 出来还是乱码 漏了一步 确认是”先 gunzip 再 base64”

八、速查卡

思路：file.bin(ZIP) -> readme(诱饵) + flag.b64(诱饵) + archive.gz(真)

真路径

gunzip -c archive.gz | base64 -d

判真伪：真 flag 符合题目格式 flag{三位_十二位十六进制}

flag{f13_f66e1b03f0b2}

附录：常见诱饵手法

手法 例子
假 flag 文件 flag.b64 解出来是 you_found_the_decoy
假 flag 明文 readme.txt 里的 nothing_to_see_here
误导提示 readme 说 xor gzip name，照做是乱码
噪音文件 noise.txt 内容只有 “nothing”
对策 先看是否符合题目格式，再多路径交叉验证
