—— 完整操作 · 详细讲解 · 易错点 · 下次速查

平台：ctf.bi6pcr.com（学校网络安全练习赛） | 题目：签到（50 分）

一、题目回顾

题目描述：连上这台服务，它会把 flag 直接打印给你。用来确认三件事——你能开启实例、能连上题目、知道 flag 要提交回平台。

本次得到的 flag（示例，平台提示每队 flag 不同）：

flag{welcome_fdb35194dc7f}

二、这道题到底在考什么（原理）

平台不直接给“IP:端口”，只给一个 WebSocket 地址（wss://…）。WebSocket 不是普通 TCP，nc 等工具无法直接连。于是需要“翻译器”把 wss 变成你本机的一个普通 TCP 端口。这个工具就是 WebSocketReflectorX（命令名 wsrx）。

数据流向：
nc → 127.0.0.1:本地端口 → wsrx（隧道） → wss://平台代理 → 题目容器

所以必须同时有：① wsrx 隧道在运行 ② nc 连那个本地端口

  • wsrx（WebSocketReflectorX）：把 WebSocket 转发成本地 TCP 端口的隧道工具（GitHub: XDSEC/WebSocketReflectorX）；
  • nc（netcat）：最简单的 TCP 连接工具，用来连本地端口、收发数据。

三、完整操作步骤（Step by Step）

Step 1 在平台创建实例、复制地址

  1. 在题目页点【创建实例】，等实例变成“运行中”；
  2. 复制它给出的 wss:// 地址（形如 wss://ctf.bi6pcr.com/api/proxy/…）；
  3. 注意实例有效期（约 120 分钟），过期要重开。

Step 2 获取 wsrx 客户端（国内网络要小心）

官方下载页：https://github.com/XDSEC/WebSocketReflectorX/releases

选择文件（Linux 虚拟机用）：wsrx-cli-0.6.1-linux-musl-x86_64.tar.gz（musl 是静态二进制，兼容性最好）。

⚠️ 国内直连 GitHub 常被拒（连接被拒绝）。用加速镜像下载（实测 ghproxy.net 可用）：

cd ~
URL=”https://github.com/XDSEC/WebSocketReflectorX/releases/download/0.6.1/wsrx-cli-0.6.1-linux-musl-x86_64.tar.gz“
wget -O wsrx.tar.gz “https://ghproxy.net/${URL}“
file wsrx.tar.gz # 必须显示 gzip compressed data 才算下对

Step 3 解压并安装（在 Ubuntu 虚拟机里）

tar -xzf wsrx.tar.gz
chmod +x wsrx
./wsrx –help # 出现 daemon/connect/serve 等帮助 = 成功

Step 4 启动隧道（终端 1）—— 保持运行，不要关

cd ~
./wsrx connect ‘wss://ctf.bi6pcr.com/api/proxy/……’

成功标志：

INFO … RX is here -> 127.0.0.1:37057 ← 这就是本地端口

⚠️ 这条命令会一直挂着，这就是“隧道”。看到端口后不要关窗口、不要按 Ctrl+C。

Step 5 用 nc 取 flag（终端 2）

  1. 按 Ctrl + Shift + T 打开一个新标签页；
  2. 连接隧道端口（端口用终端 1 显示的那个）：

nc 127.0.0.1 37057

屏幕上会直接打印出 flag，例如：

欢迎来到 CTF。这是签到题，flag 就在下面。
flag{welcome_fdb35194dc7f}

Step 6 提交 flag

  • 把整串 flag{…} 原样复制，回网页粘进输入框，点【提交 flag】；
  • 提交成功后，这道题就算完成。

四、易错点汇总（都是本次实际踩过的坑）

# 易错点 正确做法
1 直接连 GitHub 下载，连接被拒绝 用加速镜像，如 ghproxy.net / gh-proxy.com / gh.llkk.cc / ghfast.top
2 文件没下全（空/损坏），解压报 unexpected end of file 下载后先跑 file wsrx.tar.gz，确认是 gzip compressed data
3 wsrx connect 跑起来后按了 Ctrl+C，隧道断了 隧道要一直挂着，不要关、不要 Ctrl+C
4 命令打重，如 ./wsrx connect ./wsrx connect … 每条命令只写一遍
5 nc 用冒号写法 nc 127.0.0.1:37057 → missing port number nc 要空格：nc 127.0.0.1 37057
6 只有一个终端，隧道和 nc 抢着用 Ctrl+Shift+T 开新标签，或用 tmux，或把隧道放后台
7 nc 用的端口是旧的（每次启动隧道端口会变） 用本次 wsrx 显示的端口
8 提交时只复制了括号里的内容 要复制整串 flag{…}（含 flag 和花括号）
9 实例过期（约 120 分钟）后还去连 过期就重新创建实例、重新连

五、下次怎么做（速查卡 · 照着走就行）

以后遇到“容器题/连接题”，按这个顺序：

—— 连接类题目 标准流程 ——

  1. 平台【创建实例】，复制 wss://… 地址

  2. 终端1：启动隧道（保持运行，别关）
    ./wsrx connect ‘wss://…’
    → 记下输出的本地端口 127.0.0.1:XXXXX

  3. 终端2（Ctrl+Shift+T 新标签）：连端口取内容
    nc 127.0.0.1 XXXXX
    → 看到 flag{…}

  4. 整串 flag{…} 复制，回平台提交

（只有 Linux 隧道时若下载不了，用镜像：
https://ghproxy.net/<原始GitHub链接> ）

六、附录：容易混淆的语法 & 小知识

6.1 主机与端口的写法区别

工具 正确写法 说明
nc nc 主机 端口 空格分隔；写 主机:端口 会报 missing port number
ssh ssh 用户@主机 -p 端口 端口用 -p
curl curl http://主机:端口/路径 这里才用冒号
nmap nmap -p 端口 主机 端口用 -p

6.2 wsrx 常用子命令

  • daemon：后台守护进程；
  • connect：客户端（最常用），connect <wss地址> 建立本地隧道；
  • serve：服务端（搭建方用）。

6.3 小知识

  • 127.0.0.1 / localhost 都指“本机”；wsrx 把远程 wss 映射成了本机端口；
  • wsrx 和 nc 必须在“同一台机器”上：wsrx 在哪台机器跑，本地端口就在哪台机器；
  • 国内下载 GitHub 资源慢/被拒时，通用做法：在原始链接前加加速镜像前缀。
