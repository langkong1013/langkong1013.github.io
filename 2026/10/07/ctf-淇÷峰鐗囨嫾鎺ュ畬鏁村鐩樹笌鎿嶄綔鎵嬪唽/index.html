信（flag 分片，多处拼接）

langkong10132026-10-072026-10-28

零基础手算详解版 —— 注释 + Cookie + 外链 JS 三片合一，Python 代码逐行讲解

一、题目信息

项目 内容
题名 信
页面 提示”信纸被分开存放”——即 flag 被拆成几片藏在不同地方
题型 Web —— 多来源信息收集 + 拼接还原
最终 flag flag{q65_3c60fa1e978f}

二、题目现象（flag 被拆成三片）

同一个响应里，藏着三个来源的片段：

HTTP/1.0 200 OK
Set-Cookie: p=5_3c60f; Path=/
…

信

信纸被分开存放。

来源 片段 取值
① 正文 HTML 注释 flag{q6 flag{q6
② 响应头 Set-Cookie p=5_3c60f 5_3c60f
③ 外链 JS /c.js var p=”a1e978f}”; a1e978f}

按顺序拼起来：

flag{q6 + 5_3c60f + a1e978f}
= flag{q65_3c60fa1e978f}

页面那句”信纸被分开存放”，就是在明示”要收集齐全再拼”。

三、前置知识（零基础也能懂）

3.1 flag 可以”分片存放”

出题人有时不把 flag 写在一处，而是切成几段分别藏在不同位置，逼你把多个位置都收集全。缺一片就拼不出来。

3.2 常见的”存放位置”

位置 怎么拿
正文 HTML 注释 看源码
响应头 Set-Cookie curl -D - 或 F12→Network→Headers
外链 JS / CSS 访问 src= / href= 指向的文件
其它接口 JS 里 fetch 的地址

3.3 Set-Cookie 是什么

服务器在响应头里用 Set-Cookie 给浏览器”发一块数据”，浏览器之后每次请求都会带回来。在 CTF 里它常常被用来藏片段。

Set-Cookie: p=5_3c60f; Path=/
↑名字 ↑值（就是片段）

四、解题思路（为什么这么做）

  • 第 1 步：看到”信纸被分开存放”+ h2「信」，判断是分片题。
  • 第 2 步：把首页的正文、响应头、外链文件全部收集一遍。
  • 第 3 步：按”注释 → Cookie → JS”的顺序把片段拼起来。
  • 第 4 步：检查拼出来的字符串是不是 flag{...} 的标准格式。

一句话：分片题 = 多点收集 + 按序拼接；怕漏就”把能拿的都拿一遍”。

五、逐步操作（三种方式，任选其一）

方式一 浏览器（全流程手动）

  • 首页右键”查看网页源代码”→ 找到注释 flag{q6。
  • F12 → Application（应用）→ Cookies → 看到 p=5_3c60f；或 F12 → Network 看响应头。
  • 地址栏访问 /c.js → 看到 var p="a1e978f}";。
  • 三片拼起来：flag{q65_3c60fa1e978f}。

方式二 curl 三条

curl -s http://127.0.0.1:<端口>/ # 正文（含注释）
curl -s -D - -o /dev/null http://127.0.0.1:<端口>/ # 响应头（含 Set-Cookie）
curl -s http://127.0.0.1:<端口>/c.js # 外链 JS

方式三 Python（推荐，自动拼接）

import re, requests

base = ‘http://127.0.0.1:<端口>’

1) 请求首页，同时拿到：正文 + 响应头里的 Cookie

r = requests.get(base + ‘/‘)

第 1 片：正文注释里的 flag 片段

f1 = re.search(r’‘, r.text, re.S).group(1).strip()

第 2 片：响应头 Set-Cookie 里的片段

f2 = re.search(r’Set-Cookie:\s*p=([^;]+)’, str(r.headers)).group(1)

第 3 片：外链 JS /c.js 里的片段

js = requests.get(base + ‘/c.js’).text
f3 = re.search(r’”([^”]+)”‘, js).group(1)

print(f1, ‘|’, f2, ‘|’, f3)
print(‘flag =’, f1 + f2 + f3)

代码 作用 · 原理
requests.get(base + “/“) 一次请求同时拿到正文(r.text)和响应头(r.headers)
re.search(r’‘, r.text, re.S) 抓第 1 片：注释里的半截 flag
re.search(r’Set-Cookie:\s*p=([^;]+)’, str(r.headers)) 抓第 2 片：Cookie 里 p 的值
requests.get(base + “/c.js”).text 抓第 3 片的来源文件
re.search(r”\“([^\“]+)\“”, js) 抓第 3 片：JS 里引号中的字符串
f1 + f2 + f3 按顺序拼接三片，得到完整 flag

补充：只能走 wss 隧道时

import re, ssl, websocket

URL = ‘wss://ctf.bi6pcr.com/api/proxy/<实例uuid>’

def http(path):
ws = websocket.create_connection(URL, timeout=25,
header=[‘Origin: https://ctf.bi6pcr.com'],
sslopt={‘cert_reqs’: ssl.CERT_NONE})
ws.send(‘GET %s HTTP/1.1\r\nHost: 127.0.0.1\r\n’
‘Accept: /\r\nConnection: close\r\n\r\n’ % path)
buf = b’’
while True:
try:
d = ws.recv()
except Exception:
break
if not d:
break
buf += d if isinstance(d, bytes) else d.encode(‘latin1’)
ws.close()
return buf.partition(b’\r\n\r\n’)

head, body = http(‘/‘)
f1 = re.search(rb’‘, body, re.S).group(1).decode().strip()
f2 = re.search(rb’Set-Cookie:\s*p=([^;]+)’, head).group(1).decode()
js = http(‘/c.js’)[1].decode()
f3 = re.search(r’”([^”]+)”‘, js).group(1)
print(‘flag =’, f1 + f2 + f3)

代码 作用 · 原理
buf.partition(b’\r\n\r\n’) 把响应切成 head(头) 和 body(正文)
re.search(rb’Set-Cookie: …’, head) 从头里抓 Cookie 片（注意 rb 前缀=字节正则）
re.search(rb’<!– …’, body, re.S) 从正文里抓注释片

六、结果

注释片 : flag{q6
Cookie : 5_3c60f
c.js片 : a1e978f}
拼装 : flag{q65_3c60fa1e978f}

flag = flag{q65_3c60fa1e978f}

最终 flag：flag{q65_3c60fa1e978f}

七、易错点

现象 / 报错 原因 解决
只找到一两片 只在正文里找 注释/响应头/外链都要翻一遍
拼出来格式不对 顺序错或漏片 对照 flag{前缀_12位hex} 格式检查
正则匹配空 注释里含换行 加 re.S（让 . 匹配换行）或调正则
Cookie 抓不到 requests 把 Cookie 放进了 cookiejar 从 r.headers 或用 r.cookies 取

八、速查卡

思路：页面提示”分开存放” -> 收集 注释+Cookie+外链JS -> 按序拼接

curl -s http://127.0.0.1:<端口>/ # 注释片 flag{q6
curl -s -D - -o /dev/null http://127.0.0.1:<端口>/ # Cookie 片 5_3c60f
curl -s http://127.0.0.1:<端口>/c.js # JS 片 a1e978f}

结果

flag{q65_3c60fa1e978f}

附录：分片类题的”藏点清单”（挨个翻，别漏）

藏点 拿法
正文注释
响应头（Set-Cookie / X-*） curl -D - 或 F12→Network
外链 JS / CSS 访问 src= / href=
其它路径 / 接口 robots.txt、JS 里写的 URL
HTML 属性 / meta 隐藏字段、data-* 属性
