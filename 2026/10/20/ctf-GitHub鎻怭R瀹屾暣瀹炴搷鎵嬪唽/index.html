GitHub 提 PR 完整实操手册

langkong10132026-10-202026-10-28

零基础详解版 —— 以 SeimoDev/xjq 为例，从 Fork 到 PR #9 全流程复盘

包含：7 步流程 · 每行命令解释 · 4 个真实踩坑 · 报错对照表 · 可复用模板

一、这次的任务是什么

原始任务（语音转述）：

  1. 把指定仓库拉下来。
  2. 创建以自己名字命名的分支。
  3. 在分支里提交一个「自己的名字.c」代码文件。
  4. 发起 PR，申请合并到 master 分支。

实际执行结果：

项目 本次实际值
原仓库 SeimoDev/xjq
我的账号 langkong1013
默认分支 master
我的分支 gjz
提交的文件 gjz.c（7 行 C 代码）
PR 编号 #9
PR 链接 https://github.com/SeimoDev/xjq/pull/9
结果 Open（等待审核），1 file changed, +7，无冲突

一句话总结：因为这是别人的仓库，我没有推送权限，所以必须走「Fork → 在自己的副本上改 → 提 PR 回原仓库」这条标准协作路径。

二、先补基础：6 个必须懂的概念

概念 英文 一句话解释 生活比喻
仓库 Repository 一个项目的全部代码 + 历史记录 一个带时间机器的文件夹
Fork Fork 把别人的仓库复制一份到你账号下 把别人的书复印一本，你可以在复印件上随便写
克隆 Clone 把远程仓库下载到你自己电脑 把云端的书下载到本地
分支 Branch 从主线分出来的一条独立开发线 同一本书的另一个草稿本，改坏了也不影响原书
提交 Commit 把改动记录成一个”存档点” 游戏存档
远程 Remote 你本地仓库对应的云端仓库地址 本地书对应的云端备份
PR Pull Request 请求原仓库把你的改动合并进去 向原作者提交”修订申请”

最容易混的两个：

  • Fork 是「在网页上复制仓库到你账号」，Clone 是「把仓库下载到你电脑」。顺序是：先 Fork，再 Clone。
  • Commit 是「存到本地」，Push 是「传到云端」。只 Commit 不 Push，GitHub 上看不到你的改动。

2.1 为什么不能直接改 main/master

  • 别人的仓库你没有写权限，直接 push 会报 Permission denied。
  • 即使是自己的仓库，直接改主分支也不礼貌，而且很多仓库给主分支开了「保护」，根本推不上去。
  • 标准做法：一人一分支，改完提 PR，由管理员审核合并。

2.2 整体流程图

原仓库 SeimoDev/xjq
│ ① Fork（网页点一下）
▼
我的副本 langkong1013/xjq
│ ② Clone（下载到本地）
▼
本地文件夹 xjq
│ ③ 建分支 gjz
│ ④ 新建 gjz.c 并写代码
│ ⑤ Commit（存到本地）
│ ⑥ Push（传到我的副本）
▼
GitHub: langkong1013/xjq 的 gjz 分支
│ ⑦ 发 PR
▼
SeimoDev/xjq 的 master ← 等待管理员合并

三、完整实操（7 步）

第 0 步：配置 Git 身份（只做一次）

git –version
git config –global user.name “gjz”
git config –global user.email “2849486799@qq.com“

逐行解释：

  • git –version：检查是否装了 Git。有版本号输出就说明装了；提示 command not found 就去 git-scm.com 下载安装。
  • git config –global user.name “gjz”：设置提交记录里显示的作者名。–global 表示对本机所有仓库生效。
  • git config –global user.email “邮箱”：设置提交记录的邮箱。最好和 GitHub 账号绑定邮箱一致，否则 GitHub 认不出提交是你。

为什么要配：Git 每次提交都会把「作者名 + 邮箱 + 时间」写进历史。不配的话提交记录会显示成一串随机字符，PR 里也看不出是你。

第 1 步：Fork（网页操作）

操作：

  1. 打开 https://github.com/SeimoDev/xjq
  2. 点右上角的 Fork 按钮（在 Watch 和 Star 中间）
  3. 进入 Create a new fork 页面，确认 Owner 是自己的账号
  4. 点绿色按钮 Create fork

判断成功：页面跳到 https://github.com/langkong1013/xjq，并且仓库名下方出现一行小字「forked from SeimoDev/xjq」。

如果找不到 Fork 按钮：直接打开 https://github.com/SeimoDev/xjq/fork，这是 GitHub 的 Fork 专用页面，不依赖按钮。

第 2 步：Clone（下载自己的副本）

git clone https://github.com/langkong1013/xjq.git
cd xjq

逐行解释：

  • git clone 地址：把远程仓库完整下载到本地，并自动创建一个同名文件夹 xjq。
  • cd xjq：进入这个文件夹。后面所有 git 命令都必须在这里执行，否则会报 not a git repository。

关键点：地址里必须是「你的用户名」，不能是 SeimoDev。克隆错了，后面 push 一定 Permission denied。

验证：

git branch
git remote -v

  • git branch：应该看到 * master，说明克隆成功、当前在默认分支。
  • git remote -v：应该显示 https://github.com/langkong1013/xjq.git，确认是自己的副本。

第 3 步：创建自己的分支

git checkout -b gjz

逐行解释：

  • git checkout：切换分支。
  • -b：新建一个分支并立刻切过去（b = branch）。
  • gjz：分支名，用自己的名字（建议拼音，避免中文在部分系统乱码）。

验证：

git branch

输出里带 * 的那一行才是当前分支：

  • gjz
    master

第 4 步：新建 gjz.c 并写代码

新建文件：

touch gjz.c

  • touch：新建一个空文件。Windows PowerShell 里用 New-Item gjz.c。
  • 也可以在 VS Code 左侧资源管理器里右键 → 新建文件 → 输入 gjz.c。

写入代码：

#include <stdio.h>

int main(void)
{
printf(“Hello, I am gjz.\n”);
return 0;
}

逐行解释：

代码 作用 为什么这么写
#include <stdio.h> 引入标准输入输出库 printf 的声明在这个头文件里，不写会报隐式声明
int main(void) 主函数，程序入口 C 程序必须从 main 开始执行；int 是返回类型
{ } 函数体 里面放具体执行的语句
printf(“…”); 打印字符串 \n 是换行转义符；末尾分号不能少
return 0; 返回 0 告诉操作系统「程序正常结束」

可选：编译验证一下

gcc gjz.c -o gjz
./gjz

  • gcc 源文件 -o 输出名：把 C 源码编译成可执行文件。
  • ./gjz：运行它（Windows 上是 gjz.exe）。
  • 输出 Hello, I am gjz. 就说明代码没问题。没装 gcc 可以跳过，不影响提交。

第 5 步：提交（Commit）

git status
git add gjz.c
git commit -m “add gjz.c”

逐行解释：

  • git status：查看当前状态，红色字是新文件/改动。每次提交前必看，确认只改了自己想改的。
  • git add gjz.c：把文件放进「暂存区」，告诉 Git「这个文件我要提交」。建议指定文件名，不要用 git add .，避免把无关文件一起加进去。
  • git commit -m “说明”：真正生成一条提交记录。-m = message，提交说明。

验证：

git log –oneline -3

能看到 add gjz.c 这一行就成功了。本次实际是：740d1ef add gjz.c。

第 6 步：推送（Push）

git push -u origin gjz

逐行解释：

  • git push：把本地提交推到远程。
  • -u：建立「跟踪关系」，以后再推只需 git push。
  • origin：远程仓库的默认名字，clone 时自动创建，指向你的 fork。
  • gjz：要推送的分支名。

成功输出：

  • [new branch] gjz -> gjz
    branch ‘gjz’ set up to track ‘origin/gjz’.

第 7 步：发 PR

推送成功后，打开这个链接（参数已填好）：

https://github.com/SeimoDev/xjq/compare/master...langkong1013:gjz?expand=1

确认四个下拉框：

项 应该选
base repository SeimoDev/xjq（原仓库）
base master（原仓库的主分支）
head repository langkong1013/xjq（你的副本）
compare gjz（你的分支）

然后：

  • Title 填 add gjz.c
  • 点绿色按钮 Create pull request

不要点 Merge —— 合并是仓库管理员的事，你只负责发起申请。

四、怎么判断 PR 真的成功了

PR 页面出现下面这些信息，就说明完全正确：

页面信息 本次实际值 说明
标题 add gjz.c #9 #9 是 PR 编号
状态 Open 已提交，等待审核
合并去向 langkong1013 wants to merge 1 commit into SeimoDev:master from langkong1013:gjz 来源、目标、提交数都对
Commits 1 只有 1 次提交
Files changed 1（+7） 只改了 1 个文件、加 7 行
冲突检查 No conflicts with base branch 能干净合并

最关键的三个数字：Commits = 1、Files changed = 1、No conflicts。三个都对，就是标准成功的 PR。

五、本次真实踩的 4 个坑

这一节最值钱。每一步都是实际遇到并解决的。

坑 1：多行粘贴，命令被当成「续行」

现象：

PS C:\Users\langjiu\xjq> git checkout -b gjz

git status
git add gjz.c
git commit -m “add gjz.c”
nothing added to commit but untracked files present

  • 出现 >> 符号，说明 PowerShell 认为上一条命令还没结束。
  • git add 实际没执行，所以 git commit 一开始提示 nothing added。

原因：

把多行命令一次性粘进 PowerShell，末尾的引号/换行让终端误判为「命令还没写完」，于是把后续行当成续行内容。

解决：

  • 一条一条执行，执行完看到提示符 PS …> 再敲下一条。
  • 如果已经乱了，按 Ctrl + C 取消当前输入，回到干净提示符。

教训：终端不是聊天框，逐条执行最稳。

坑 2：push 报 Connection was reset

现象：

fatal: unable to access ‘https://github.com/langkong1013/xjq.git/‘: Recv failure: Connection was reset

原因：

  • 不是你操作错了，是国内访问 GitHub 网络不稳定，连接被中断。
  • 也可能是认证没完成（GitHub 早就不允许用账号密码推送）。

解决：

  1. 直接重试一次：有时只是瞬时抖动。
  2. 用浏览器登录认证：弹出 Git Credential Manager 窗口时，选 Sign in with your browser，登录后自动记住凭据。本次就是这样成功的。
  3. 有代理软件（Clash / V2Ray）时给 git 配代理：

git config –global http.proxy http://127.0.0.1:7890
git config –global https.proxy http://127.0.0.1:7890
git push -u origin gjz

  1. 没有代理时：连手机热点再推，往往能通。
  2. 还不行：改用 SSH，并把端口改成 443（见下一节）。

先查代理端口通不通：

Test-NetConnection 127.0.0.1 -Port 7890

  • TcpTestSucceeded : True 表示端口通；False 说明端口不对（V2RayN 常见 10809，Clash 常见 7890）。

坑 3：VS Code 提示「受限模式」

现象：

打开文件夹后，顶部出现黄色横幅：受限模式，信任此文件夹以启用所有功能。终端和部分 git 功能可能被限制。

解决：

  • 点横幅里的「管理」→ 选「信任」→ 确认「是，我信任此作者」。
  • 处理成功后，左下角状态栏的「受限模式」会消失。

坑 4：clone 错了仓库

现象：

push 时报 Permission denied，或者 remote: Permission to SeimoDev/xjq.git denied。

原因：

clone 的是原仓库 SeimoDev/xjq，而不是 fork 后的 你的用户名/xjq。你对原仓库没有写权限。

解决：

git remote -v
git remote set-url origin https://github.com/你的用户名/xjq.git

  • git remote -v：查看当前远程地址。
  • git remote set-url origin 新地址：把远程地址改成你自己的 fork，不用重新 clone。

六、常见报错对照表

报错 原因 解决
not a git repository 不在仓库目录里 cd 进仓库文件夹
Authentication failed 用了账号密码 用浏览器登录，或 Personal Access Token
Permission denied 克隆成了原仓库 改成自己的 fork 地址
src refspec … does not match any 分支没建 / 名字打错 git branch 确认分支名
nothing to commit 文件没保存 / 没 add Ctrl+S 保存，再 git add 文件名
Connection was reset 网络被重置 重试 / 浏览器登录 / 配代理 / 换热点
There is nothing to compare PR 的 base 和 compare 选反了 base 选原仓库 master，compare 选自己的分支
This branch has conflicts 和主分支有冲突 先同步主分支再解决冲突
fatal: remote origin already exists 已存在名为 origin 的远程 用 git remote set-url origin 新地址

0. 配置身份（只做一次）

1. 克隆自己的 fork

git clone https://github.com/langkong1013/xjq.git

2. 建分支

git checkout -b gjz
git branch # 确认带 * 的是 gjz

3. 建文件（然后写入代码并保存）

touch gjz.c

4. 提交

git status # 确认只多了 gjz.c
git add gjz.c
git commit -m “add gjz.c”
git log –oneline -3 # 确认提交存在

5. 推送

git push -u origin gjz

6. 发 PR（浏览器打开）

https://github.com/SeimoDev/xjq/compare/master...langkong1013:gjz?expand=1

八、以后复用模板（换两个名字就行）

以后遇到任何「给仓库提 PR」的任务，只要替换两个值：

占位符 含义 本次的值
<你的用户名> 你 GitHub 账号名 langkong1013
<你的名字> 分支名 / 文件名 gjz

git clone https://github.com/<你的用户名>/<仓库名>.git
cd <仓库名>
git checkout -b <你的名字>
touch <你的名字>.c

写代码 → 保存

git add <你的名字>.c
git commit -m “add <你的名字>.c”
git push -u origin <你的名字>

然后到原仓库页面点 Compare & pull request

唯一需要注意的三件事：

  • clone 的地址一定是自己的 fork，不是原仓库。
  • PR 的 base 是原仓库的 master，head 是自己的分支。
  • 不要点 Merge，只发起 PR。

九、完成自检清单

  • 仓库已 Fork，页面显示 forked from SeimoDev/xjq。
  • 本地 git remote -v 指向自己的用户名。
  • git branch 里带 * 的是自己的分支 gjz。
  • 文件名为 gjz.c（不是 .cpp / .txt / Untitled）。
  • git log 里能看到 add gjz.c 这条提交。
  • git push 成功，输出 new branch。
  • PR 页面：Commits = 1，Files changed = 1，No conflicts。
  • 没有点 Merge。

全部打勾，任务完成。
