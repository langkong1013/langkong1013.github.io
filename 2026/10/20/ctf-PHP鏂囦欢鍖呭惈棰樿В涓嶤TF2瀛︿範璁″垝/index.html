零基础详解版 —— 从一道 LFI 题讲起，并把学习计划调整到 CTF² 平台

题目：source.php / hint.php 文件包含　|　flag：CTF2{0aaec924-feed-4b80-ba0d-2151603f9a25}

一、题目信息

项目 内容
题目地址 http://96aa0bc45a43f3ff3d55a028.http-ctf2.dasctf.com/
方向 Web
考点 PHP 文件包含（LFI）+ 白名单校验绕过 + 目录穿越
关键提示 源码注释 ；hint.php 说 flag 在 ffffllllaaaagggg
最终 flag CTF2{0aaec924-feed-4b80-ba0d-2151603f9a25}
一句话思路 校验函数只看问号前面的 source.php，但 include 用的是整串，于是用 source.php?/../../.. 把校验骗过去，再穿越目录读到目标文件。

二、解题过程（5 步）

2.1 第一步：看页面源码

打开题目，页面只有一张图片。按 Ctrl+U 看源码，发现一条 HTML 注释：

这是出题人给的第一个提示：去看 source.php。HTML 注释在页面上不显示，但源码里有——这就是”画面 ≠ 源码”的典型例子。

2.2 第二步：访问 source.php 读源码

在地址后面加 /source.php：

http://题目地址/source.php

2.3 第三步：访问 hint.php 拿目标文件名

http://题目地址/hint.php

返回：

flag not here, and flag in ffffllllaaaagggg

意思是：flag 不在 hint.php，在 ffffllllaaaagggg 这个文件里。

2.4 第四步：构造 payload

直接传 file=ffffllllaaaagggg 会被白名单拦下。正确写法：

http://题目地址/?file=source.php?/../../../../ffffllllaaaagggg

拆开看：

片段 作用
?file= 参数名，源码里用 $_REQUEST[“file”] 接收
source.php? 让白名单校验通过的前缀
/../../../../ 目录穿越：每段 ../ 向上一级，四段跳出 web 根目录
ffffllllaaaagggg 真正要读的文件

2.5 第五步：拿到 flag

页面返回：

CTF2{0aaec924-feed-4b80-ba0d-2151603f9a25}

复制这一整串提交即可。注意：本平台容器题的 flag 格式是 CTF2{…}，不是 flag{…}。

三、源码逐行讲解

代码 作用 漏洞点
highlight_file(FILE) 把当前文件源码高亮输出 方便做题人看代码
$whitelist = […] 白名单只允许 source.php、hint.php 思路是”只放行两个文件”
in_array($page, $whitelist) 整体完全相等才放行 严格匹配，直接传目标文件名会被拒
mb_strpos($page . “?”, “?”) 找第一个问号的位置 只关心问号之前的内容
mb_substr($page, 0, 位置) 截取问号之前的字符串 问号之后写什么都不检查
urldecode($page) URL 解码后再判断一次 防止用编码绕过
include $_REQUEST[“file”] 包含并执行该文件 用的是完整字符串，不是截断后的

整段代码的核心矛盾：

  • 校验时：把字符串在第一个问号处”切断”，只看 source.php。
  • 执行时：include 拿到的是”整串”，包括问号后面的目录穿越。
  • 两者不一致，就产生了绕过空间。

四、payload 为什么能过校验

以 file=source.php?/../../../../ffffllllaaaagggg 为例，走一遍流程：

  1. 先判断整体是否等于白名单：不等于，继续。
  2. 找第一个问号位置，截取前面部分，得到 source.php。
  3. source.php 在白名单里 → 校验通过，返回 true。
  4. include 收到完整字符串 source.php?/../../../../ffffllllaaaagggg。
  5. ../ 逐级向上，跳出 web 根目录，最终定位到 ffffllllaaaagggg。
  6. 文件内容被包含并输出 → 页面显示 flag。

一句话：校验看的是”问号前”，执行用的是”整串”。

五、文件包含题的通用套路

类型 特征 典型 payload
本地文件包含 参数进入 include ?file=../../etc/passwd
白名单 + 问号截断 校验只看到问号前 ?file=source.php?/../../flag
二次编码绕过 过滤了 ../ ?file=%252e%252e%252f
php://filter 读源码 想读 PHP 源码而不是执行 ?file=php://filter/convert.base64-encode/resource=index.php
php://input 执行代码 allow_url_include 开启 POST body 写 PHP 代码
日志包含 包含 access.log ?file=../../var/log/nginx/access.log
伪协议 data:// 直接执行数据 ?file=data://text/plain;base64,PD9waHA…

做题顺序建议：先看源码 → 找 include 点 → 看有没有过滤/白名单 → 选对应绕过方式。

六、易错点

坑 说明
直接传目标文件名 不在白名单，被拒
漏掉问号 source.php/../.. 不匹配白名单
curl 测试时 ../ 被吃掉 要加 –path-as-is，否则 curl 自动归一化路径
目录层数不对 本题 4 层刚好；太少跳不出根目录
flag 格式照抄 本题是 CTF2{…}，不是 flag{…}
环境过期 容器有时限，过期重新开

七、CTF² 是什么

你做题的域名是 xxx.http-ctf2.dasctf.com，说明你用的是 CTF² 平台。

项目 内容
平台名称 CTF²（BUUCTF 新平台）
网址 https://ctf2.dasctf.com
特点 BUUCTF 的升级版，题目容器化，每个题给一个独立域名
主要栏目 训练（每日一练 + 公开练习场）、赛事、排行榜等
题目板块 公开练习场分为多个板块，其中 BUUCTF 板块就是旧平台的经典题
flag 格式 容器题多为 CTF2{uuid}；老题可能是 flag{…}，以题目页说明为准

和你之前找的攻防世界相比：攻防世界新版已经取消”新手区”，题目打包成整届比赛题集；CTF² 的公开练习场更适合新手按板块刷。

八、CTF² 做题流程（5 步）

  1. 打开 https://ctf2.dasctf.com，注册并登录。
  2. 点顶部「训练」→ 选「公开练习场」→ 找到 BUUCTF 板块并报名。
  3. 在板块里按方向筛选（Web / Misc 等），点开一道题。
  4. 点「开启容器 / 启动靶机」，等十几秒，得到一个 xxx.http-ctf2.dasctf.com 的地址。
  5. 浏览器打开该地址做题，找到 flag 后回到题目页提交。

每日一练：系统每天推一道精选题，做完或到时间才解锁下一道，适合保持手感。

注意事项：

  • 容器有时限，过期要重新开启，之前拿到的地址会失效。
  • 每道题的容器地址都不同，别拿 A 题的地址做 B 题。
  • 提交前确认 flag 格式和大小写，别多带空格。
